# CoursePlatform API (.NET 10)

An empty, production-shaped starting point for new APIs. It contains **only the
architecture**: layering, persistence plumbing, authentication, error handling,
logging and a generic CRUD base — no business features.

The solution was converted from the former `GRAFM-Etisalat` projects (net8.0,
Dynamics CRM / SharePoint persistence) to a reusable **.NET 10 / EF Core**
template.

---

## Projects

```
CoursePlatform.slnx
│
├── CoursePlatform.Domain          no dependencies
├── CoursePlatform.Application     -> Domain
├── CoursePlatform.Infrastructure  -> Application (EF Core, Serilog, JWT)
└── CoursePlatform.Api             -> Infrastructure
```

Dependencies point inwards only. `Domain` and `Application` never reference EF
Core, ASP.NET Core or any other infrastructure concern.

| Project | Contains |
| --- | --- |
| **Domain** | `BaseEntity` (identity + audit + soft delete), repository and unit-of-work contracts, pure enums and aggregates. |
| **Application** | Use cases, DTOs, mapping, service abstractions (`ILogService`, `ITokenProvider`, `ICurrentUserService`, …), application exceptions, generic CRUD base service, DI module. |
| **Infrastructure** | `ApplicationDbContext`, entity configurations, EF repositories, unit of work, audit interceptor, password hashing, JWT issuing, Serilog, startup migration/seeding, DI module. |
| **Api** | `Program.cs`, generic CRUD controller base, auth controller, JWT/OpenAPI extensions, exception middleware, configuration. |

---

## What is included

- **Layered solution** on `net10.0` with a shared `Directory.Build.props` and a
  pinned SDK in `global.json`.
- **EF Core 10 + SQL Server** with `DbContext`, per-entity `IEntityTypeConfiguration`,
  a generic repository, a unit of work and a design-time factory for `dotnet ef`.
- **Auditing and soft delete** applied automatically by a `SaveChangesInterceptor`:
  `CreatedAtUtc/CreatedBy` and `LastModifiedAtUtc/LastModifiedBy` are stamped from
  the current principal, and deletes of `ISoftDeletable` entities become updates.
- **JWT authentication** (`POST api/auth/login`, `POST api/auth/register`,
  `GET api/auth/me`) with PBKDF2-SHA256 password hashing (salt + configuration
  pepper, iteration count stored alongside the hash).
- **Generic CRUD base** (`BaseController<TEntity, TGetDto, TPostDto>` +
  `GenericBaseService<TEntity, TGetDto, TPostDto>`) so a feature only supplies
  its DTO mapping.
- **One error envelope** for every failure (`status`, `message`, `errors`,
  `traceId`) produced by `ExceptionHandlingMiddleware`.
- **Serilog** request logging and rolling file sinks driven by configuration.
- **OpenAPI** document generated by ASP.NET Core with the Swagger UI on
  `/swagger`, including a bearer security definition.
- **Pagination** primitives: `PagedRequest` (validated page number/size) and
  `BaseSearchResult<T>` (`TotalCount` + `Results`).

Deliberately **not** included: any KPI / issue-tracker / survey / file-log
feature, Dynamics CRM, SharePoint, `Microsoft.Xrm.Sdk`, AutoMapper and
FluentValidation. Add them back per feature if a new project needs them.

## Getting started

```bash
dotnet restore
dotnet build
dotnet run --project CoursePlatform.Api
```

Swagger UI: <http://localhost:5147/swagger>

In `Development` the API applies migrations and seeds an administrator:

| Setting | Value |
| --- | --- |
| Email | `admin@localhost` |
| Password | `Admin#12345` |

Change or remove the `Seed` section outside development.

### Configuration

Secrets are **not** stored in the repository. Set them with user secrets or
environment variables before running outside development:

```bash
dotnet user-secrets set "Security:PasswordPepper" "<random string>" --project CoursePlatform.Api
dotnet user-secrets set "JwtSettings:SecretKey" "<at least 32 random characters>" --project CoursePlatform.Api
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "<sql server connection string>" --project CoursePlatform.Api
```

| Key | Purpose |
| --- | --- |
| `ConnectionStrings:DefaultConnection` | SQL Server connection (defaults to LocalDB). |
| `Database:ApplyMigrationsOnStartup` | Run `MigrateAsync` at startup (dev only). |
| `Database:SeedOnStartup` | Seed the administrator account (dev only). |
| `Security:PasswordPepper` | Global pepper appended to every password before hashing. |
| `JwtSettings:*` | Issuer, audience, lifetime and signing key. |
| `Swagger:Title` / `Swagger:Version` | OpenAPI document name and URL. |
| `Serilog:*` | Sinks and levels. |

### EF Core commands

The `dotnet-ef` tool is pinned locally in `dotnet-tools.json`:

```bash
dotnet tool restore

dotnet ef migrations add <Name> \
  --project CoursePlatform.Infrastructure \
  --startup-project CoursePlatform.Api \
  --output-dir Persistence/Migrations

dotnet ef database update \
  --project CoursePlatform.Infrastructure \
  --startup-project CoursePlatform.Api
```

## Adding a feature

A feature touches all four layers. Example — `Order`:

1. **Domain** — add `Entities/Order.cs` deriving from `BaseEntity`.
2. **Application** — add `Features/Orders/` with `Dtos/OrderDto`,
   `Dtos/PostOrderDto`, `Interfaces/IOrderService` and
   `Implementation/OrderService : GenericBaseService<Order, OrderDto, PostOrderDto>`
   providing `MapToDto`, `MapToEntity` and `ApplyDto`. Register it in
   `ResolveDependencies`.
3. **Infrastructure** — add `Persistence/Configurations/OrderConfiguration.cs`
   (table mapping, lengths, indexes and `HasQueryFilter(x => !x.IsDeleted)`), then
   create a migration.
4. **Api** — add `Controllers/OrdersController : BaseController<Order, OrderDto, PostOrderDto>`.

If a feature needs a different persistence technology, implement the Domain
repository interfaces in a new project and swap the registration in
`Infrastructure/ResolveDependencies.cs`.

## Conventions

- Feature services are registered as `interface -> internal implementation`.
- Repositories are generic; add feature-specific queries via
  `IBaseRepository<T>.Query()` instead of growing the generic contract.
- Throw the exceptions in `Application/Common/Exceptions`; the API maps them to
  HTTP status codes in one place.
- Validate request DTOs with data annotations (enforced by `[ApiController]`) and
  business rules with the `ValidateAsync` hook of the generic service.
- Every new entity gets an EF configuration class and a query filter if it is
  soft deletable.
